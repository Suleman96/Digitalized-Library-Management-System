Search: FAISS Only
Search

v1 used a single-strategy search: embed the query with all-MiniLM-L6-v2, then find the nearest vectors in the FAISS index by inner product (equivalent to cosine similarity on L2-normalised vectors). 

# v1 search — raw FAISS only
q_vec = model.encode([query])
distances, indices = index.search(q_vec, k)
results = [metadata[i] for i in indices[0]]
⚠️
Problem: A search for "Christie murder mysteries" would find semantically similar books but miss exact keyword matches like an author named "Christie" — FAISS alone doesn't understand proper nouns as reliably as keyword search.

RAG Pipeline — How It Works
AI Pipeline
💡
RAG = Retrieve → Augment → Generate. Instead of asking an AI to answer from memory, we first retrieve relevant books, then hand them to the AI as context. In Iqra v2, RAG has three optional enhancement stages that make retrieval dramatically more accurate.

Stage 0 — Baseline: Hybrid Search

Every search goes through the HybridRetriever regardless of AI settings:

# hybrid_retriever.py — always active
bm25_scores   = bm25.get_scores(query.lower().split())      # keyword match
faiss_scores  = faiss_index.search(embed(query), k=pool)   # semantic match
combined      = 0.40 * minmax(bm25) + 0.60 * minmax(faiss) # weighted fusion

Advanced RAG via rag_pipeline.py (optional, requires AI)

Pre-retrieval · Stage A — HyDE

Hypothetical Document Embeddings: The LLM generates a fake 2-sentence ideal book description for the query. That synthetic text is embedded and searched in FAISS — producing richer semantic results than embedding the raw query, because the hypothetical doc "looks like" a book in the index.

prompt = "Write a 2-sentence description of an ideal book for: '{query}'"
hypo_doc = llm.generate_hypothetical_doc(query)
hyde_results = retriever.search(hypo_doc, k=fetch_k)
Pre-retrieval · Stage B — Multi-Query

Query Variants + RRF: The LLM generates 3 alternative phrasings of the query. Each variant runs through the full hybrid retriever. Results from all N+1 searches are merged using Reciprocal Rank Fusion — books appearing in multiple result lists get boosted, catching books that any single query might miss.

variants = llm.generate_query_variants(query)  # 3 alternatives
all_results = [retriever.search(q, k) for q in [query] + variants]
merged = rrf_merge(all_results)  # 1/(rank + 60) scoring
Post-retrieval · Stage C — Cross-Encoder Re-ranking

Second-Pass Precision: After retrieval, every (query, title + description) pair is scored by a cross-encoder model (ms-marco-MiniLM-L-6-v2). Unlike bi-encoders that embed query and doc separately, a cross-encoder sees both together — dramatically improving relevance precision at the cost of speed. Results are re-ordered by the cross-encoder score.

pairs = [(query, f"{r['title']} {r['description'][:300]}") for r in results]
ce_scores = cross_encoder.predict(pairs)
results = sorted(zip(ce_scores, results), reverse=True)
✅
All three stages are independently toggleable and gracefully degraded: if the LLM is off or the cross-encoder can't load, the pipeline falls back to plain hybrid search without raising an exception.

Comparison: RAG strategies

StrategyWhen it helps mostCost
Hybrid (always on)All queries — baseline improvement over FAISS-onlyNegligible (+1ms)
Query ExpansionVague queries ("something motivating")1 LLM call (~0.5s)
HyDEAbstract/thematic queries ("a book about resilience")1 LLM call + 1 FAISS search
Multi-QueryAmbiguous phrasing ("hacking stories")1 LLM call + 3 FAISS searches + RRF

config.py — Settings Hub

A frozen @dataclass holding every path, API key source, and option list. All other modules import from here — a single source of truth.

🔒
Frozen dataclass raises FrozenInstanceError if any code tries to mutate a setting at runtime. Tests must replace the entire module-level settings reference using patch("module.settings", SimpleNamespace(...)) — setattr won't work.

class Settings:
    base_dir: Path = Path(".")

    @property
    def google_api_key(self) -> str:
        # Priority 1: env var → 2: .env file → 3: API.txt
        ...

manager.py — Catalogue Manager

Owns the local book collection: CSV on disk, FAISS index in memory, metadata pickle.

Storage formatPurposeWho reads it

🐛
v1 bug fixed: The old add_book called _load_or_build() which reloaded the CSV from disk before the new row was saved — silently discarding additions. v2 operates on the in-memory DataFrame and only persists at the end.

recommender.py — Search Engine

Semantic search over the FAISS index + Google Books API, with result normalisation and HTML rendering.

Every piece of text from outside (CSV data, API responses) is passed through html.escape() before HTML insertion — XSS prevention at the boundary.

hybrid_retriever.py — BM25 + FAISS Fusion

⚙️
No LangChain dependency. LangChain 1.3.1 removed EnsembleRetriever from both langchain and langchain-community. The hybrid retriever is implemented directly with rank_bm25 and raw faiss — zero framework dependency.
# Scoring formula (per document):
combined = 0.40 * minmax(bm25_scores) + 0.60 * minmax(faiss_scores)

# Why min-max normalise?
# BM25 scores are unbounded (0 → ∞). FAISS cosine scores are in [-1, 1].
# Without normalisation, BM25 scale would dominate regardless of weight.

A singleton LLMProvider that connects to any of four backends under one interface. Never raises — all failures return empty strings and log warnings.

agent.py — Conversational Library Agent

A LangGraph ReAct agent that reasons in a loop: Think → Use a tool → Observe result → repeat. Per-session memory via MemorySaver, keyed by UUID thread_id.

reading_list.py — Bookmarks

Personal reading list stored as data/reading_list.json (git-ignored). JSON was chosen over CSV because it's simpler for atomic single-object writes and keeps personal data separate from the catalogue.

exporter.py — PDF Generation

Pure-Python PDF export via fpdf2. Uses _safe_str() to encode all text as latin-1 with errors='replace' — handles Arabic, CJK, and emoji titles without crashing the built-in Helvetica font.

app.py — Gradio Application

7-tab UI wiring all components together. Startup sequence:

manager          = DynamicBookManager()    # loads CSV, builds FAISS
reco             = BookRecommender()       # loads FAISS + embedding model
reading_list_mgr = ReadingList()           # loads JSON
hybrid_ret       = HybridRetriever()
hybrid_ret.build(embed_fn=reco._embed)    # reuses reco's loaded model
rag_pipeline     = RAGPipeline(hybrid_ret, llm)
agent_mgr        = LibraryAgent(...)       # agent built only after Connect
♻️
hybrid_ret.build(embed_fn=reco._embed) — the embed function is shared, not reloaded. Loading all-MiniLM-L6-v2 takes ~3s. Passing it in avoids loading it twice at startup.

Embedding Model: all-MiniLM-L6-v2
AI Pipeline
PropertyValue
Model size22 MB (very lightweight)
Output dimensions384 float32 per text
Training data1 billion sentence pairs (distilled from larger models)
Speed (CPU)~1,000 sentences/second
FAISS index typeIndexFlatIP — exact inner product search
NormalisationL2-normalised: inner product = cosine similarity

Why L2-normalise? After normalisation, cosine similarity equals dot product. IndexFlatIP computes dot products (inner products) — so the highest scores are the semantically closest books. This is exact search: no approximation, no recall trade-off. At 6,810 books it runs in <10ms.

Cross-encoder model: cross-encoder/ms-marco-MiniLM-L-6-v2 (~70MB) is loaded lazily only when re-ranking is requested. It accepts pairs of texts rather than individual embeddings, which is why it's more accurate but slower than bi-encoders.

Deployment
  • Copy .env.example → .env and fill in GOOGLE_API_KEY

How to Extend
Extensibility

Add a new AI provider

  1. Add to PROVIDER_MODELS in llm_provider.py
  2. Add _connect_<provider>() method
  3. Add if self._provider == "..." branch in _call()
  4. Add get_langchain_llm() branch for agent support
  5. Add optional package to requirements.txt

Add a new RAG stage

  1. Add method to llm_provider.py if LLM needed
  2. Add use_new_stage: bool = False param to RAGPipeline.search()
  3. Implement inside the search method with try/except fallback
  4. Add checkbox to app.py UI and wire to _search_inputs
  5. Add tests in test_rag_pipeline.py

Scale beyond 6,810 books

<100k booksCurrent setup works fine — no change needed
100k–1M booksSwitch FAISS to IndexIVFFlat (approximate, faster)
>1M booksConsider ChromaDB or Qdrant with persistent storage

Glossary
Infrastructure
RAG
Retrieve relevant documents first, then ask the AI to answer using them as context — not from memory alone.
HyDE
Hypothetical Document Embeddings: the LLM generates a fake ideal answer; its embedding is used for retrieval instead of the raw query.
RRF
Reciprocal Rank Fusion: merges multiple ranked lists by scoring each doc as Σ 1/(rank + 60). Books appearing in multiple lists get boosted.
Cross-encoder
A model that scores a query–document pair jointly (sees both texts at once) — more accurate than bi-encoders but slower.
Bi-encoder
Encodes query and document separately, then compares embeddings. Fast but less precise than cross-encoders.
BM25
Best Match 25 — a classic keyword ranking algorithm used in Elasticsearch. Handles exact terms, proper nouns, and rare words well.
FAISS
Facebook AI Similarity Search — library for fast approximate and exact vector search.
IndexFlatIP
FAISS index type: exact inner product search. On L2-normalised vectors, inner product equals cosine similarity.
Embedding
Converting text into a fixed-size vector of numbers that captures its semantic meaning.
LangGraph
Framework for building stateful AI agents as directed graphs. Powers the ReAct conversational agent.
ReAct
Reason + Act: agent strategy where the model alternates between thinking and calling tools until it has enough information to respond.
MemorySaver
LangGraph component that stores conversation history in memory, keyed by thread_id (one per browser session).
